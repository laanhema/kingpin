# Multi-Harness Architecture

[Back to the README](../README.md).

Each supported harness uses native configuration and hook mechanisms without dirtying repository tracking:

- **Claude Code**: Workspace trust in `~/.claude.json`. System prompt via `--append-system-prompt-file`. Turn end via `worker/hooks.json`, whose Stop command runs `bin/kingpin-stop`.
- **Antigravity CLI**: Workspace trust in `~/.gemini/antigravity-cli/settings.json`. Rules in `.agents/rules/kingpin.md`, which needs a `trigger: always_on` frontmatter: agy skips a rules file without one, without a word. Turn end via `.agents/hooks.json`, whose Stop command runs `bin/kingpin-stop`.
- **OpenCode**: Autonomous permissions via `--auto`. Instructions in `.opencode/opencode.json`: OpenCode reads `opencode.json` or `.opencode/opencode.json`. Turn end via `.opencode/plugins/kingpin-stop.js`, which calls `bin/kingpin-stop`.
- **The orchestrator contract** (issue #96): tracked as `orchestrator/contract.md` and installed only in the main checkout, into `~/.kingpin/orchestrator.md`, `.claude/rules/kingpin-orchestrator.md` and `.agents/rules/kingpin.md`, with `.opencode/opencode.json` pointing at `~/.kingpin/orchestrator.md`. A spawned worker gets `worker/preamble.md` and none of these files.

`bin/kingpin-scope` (`kingpin scope files`) lists the instruction files a harness really loads for a worktree, and `kingpin scope check` exits 1 naming the file when one of them carries the contract; `kingpin spawn` runs it before it opens a window.

Kingpin-injected worktree configuration files (`.agents/rules/kingpin.md`, `.agents/hooks.json`, `.opencode/opencode.json`, the historical `.opencode/config.json` described below, `.opencode/plugins/package.json`, and `.opencode/plugins/kingpin-stop.js`) stay out of `git status` in a leased worktree through an exclude file Kingpin owns (`~/.kingpin/tasks/<task-id>/exclude`), which that worktree reads through a worktree-scoped `core.excludesFile` (`lib/exclude.sh`). The file the worktree would otherwise inherit is mirrored into the task's file, because the worktree-scoped setting replaces it; a configured ignore file that exists but cannot be read refuses the spawn instead of dropping your rules without a word. The main checkout's `.git/info/exclude` is your file: a linked worktree shares the common dir, so a spawn that appended to it changed your repository on every task and deleted lines it never wrote, and it never writes it now. The only part of it `kingpin guard install` rewrites is the `# kingpin guard` … `# end kingpin guard` block that it writes for its three main-checkout contract copies: the install rewrites the block on every run, and it adopts a loose copy an older version left in the file instead of adding a second line, so one install silences the warning. It may also append a plain `.claude/settings.local.json` line outside the block, when your project does not already ignore that file. `kingpin spawn` names every Kingpin-shaped line outside that block (a broad `.agents/` or `.opencode/` one, or an unmaintained exact path such as `.agents/hooks.json` or the `.opencode/plugins/*` pair) and leaves it for you to remove; it skips the block. The worktree-scoped setting needs git's `extensions.worktreeConfig` flag, which `kingpin spawn` sets once in the project repository; the flag changes no ignore rule by itself. `kingpin done` removes the pointer, the harness files that spawn injected and the task's exclude file, so a pool slot goes back clean for the next lease. A spawn also examines the slot it leased for the harness files an earlier task's cleanup left behind: an older Kingpin hid those through the main checkout's `.git/info/exclude`, so treehouse could hand the slot out as clean and the files surfaced once that line was removed. It deletes one only when the content proves Kingpin wrote it: the agy Stop hook whose only top-level key is `kingpin`, the agy rules file with Kingpin's `trigger: always_on` frontmatter above the worker preamble, the old OpenCode `.opencode/config.json` whose only keys are `permission` and `instructions` pointing into `$KINGPIN_HOME`, and the OpenCode plugin pair, a package file that is exactly Kingpin's and a stop script carrying Kingpin's hook. Each of those is a shape Kingpin itself writes at that path, so the proof holds whatever harness the earlier task ran; `.opencode/opencode.json` is the exception, because it is your project's config as much as Kingpin's, which is why a spawn merges into it and never deletes it. Any other file at a Kingpin path, and any other untracked file, is left in place and named on stderr, because the slot is a checkout of your repository and a delete is not reversible. If those leftovers have already surfaced, treehouse will not lease the dirty slot, so this sweep never runs on it: `treehouse return --force <path>` cleans the slot and puts it back in the pool. Your own `.agents/` and `.opencode/` files stay visible in `git status`, because no broad line is written for you.

`.gitignore` ignores `.agents/plans/`, `.agents/reports/` and `.agents/reviews/`. They hold local working artifacts (plans, implementation reports, reviews and prototype patches) that agents write while they work, so they are not tracked. Other files under `.agents/`, such as a PRD, stay trackable. An ignore rule never untracks a path that is already in the index, so `./tests/lint.sh` fails on any tracked path under those three directories; the remedy it prints is `git rm --cached <path>`, which leaves the file on disk and ignored.
